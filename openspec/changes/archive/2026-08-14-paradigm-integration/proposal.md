## Why

前两轮(`evolp-dlp-mop`、`full-chain-paradigms-aop`)以「自包含运行时模块 + 内联测试」落地了 12 类逻辑范式与 8 类编程范式 + AOP,但那些实现是**语义演示**:范式之间、范式与类型/效应/值系统之间没有真正的接入接口,无法被其他必要特性组合使用。这里澄清「可组合性」的正确含义——它**不是语义自举**(用「组合既有特性」来近似替代范式自身语义),而是**可接入性**:每个范式是 Rust 中一等设施,暴露清晰的集成接口,当其他必要特性(静态类型、代数效应、线性/分级等级、并发、FRP、OOP、进程演算)要组合使用时能够真正插接进去。本变更把全部 21 个范式(12 逻辑 + 8 编程 + AOP)在 Rust 中重新实现为一等设施,补齐接入接口并贯通到全链路(源码 → desugar → 类型/效应/等级 → 求值),直到端到端可用。

## What Changes

- **范式一等化**:每个范式(12 逻辑 + 8 编程 + AOP)在 Rust 中实现为带集成接口的一等设施(公开 trait / 模块 API / AST 节点 / 类型构造 / 效应操作),替换此前「自包含语义演示」式实现。
- **组合 = 可接入(非语义自举)**:定义统一接入抽象(值 `Value`、类型 `Type`、效应 `EffectRow`、等级 `Grade`),每个范式通过该抽象与其他特性互操作;范式自身语义由自身求值器实现,不靠「组合既有特性」来替代。
- **全链路接线**:21 个范式从 Tisp 源码可书写,贯通 lexer/reader → desugar(`CoreExprNode`)→ 类型推断 → 效应/等级检查 → 解释器求值,直到 `--run` 端到端可用。
- **副作用接入**:范式副作用(栈顶、状态机态、数组缓冲、流缓冲、自动机搜索、概率分布)统一接入既有代数效应/单子(`State`/`Search`/`Signal` 等),单处理器路径走 §12.6 直接状态线程降级。

## Capabilities

### New Capabilities

- `paradigm-integration`: 21 个范式(12 逻辑 + 8 编程 + AOP)的一等化接入接口、跨范式组合(共享抽象)与全链路接线契约。

### Modified Capabilities

(无——范式行为规格已在前两轮 delta 中定义;本变更聚焦「实现为可接入的一等设施并贯通全链路」,为集成层新能力。)

## Impact

- **tisp-core**:新增范式 AST 节点与类型构造(数组/符号/自动机/状态机等),统一值/类型接入抽象;`Value` 扩展范式值。
- **tisp-frontend**:reader/desugar 识别 21 个范式的语法形式并脱糖为 `CoreExprNode`。
- **tisp-middle**:类型推断/效应/等级接入各范式;范式类型参与 HM 推断,范式副作用参与效应行与 grade_check。
- **tisp-backend**:interpreter 注册各范式求值器(经统一接口),LLVM codegen 对范式做基础降级。
- **tisp-runtime**:范式模块从「语义演示」升级为「一等设施」(公开 trait + 可接入 API)。
- **docs/spec.md** / **standard_doc** / **CHANGELOG**:同步集成架构说明与实现状态。
